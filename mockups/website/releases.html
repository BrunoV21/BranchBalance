v1.0.0 Preview

The first complete BranchBalance product loop, plus trip-aware spending intelligence. The implementation is in place; physical-device acceptance is the remaining release gate.

What is in this preview

GitHub-backed groups

Device-flow sign-in, rotating credentials, private repositories, and collaborator invitations.

Complete expense lifecycle

Add, edit, and delete dated expenses with conflict detection and deterministic shares.

Balances and settlements

Per-person paid totals, net balances, and a concise deterministic settlement list.

Spending intelligence

Group budgets, category limits, payment methods, filters, trip dates, and daily guidance.

Highlights

  • Create a group as a private branch-balance-<slug> repository and invite GitHub users as members.
  • Split an expense equally, assign it in full to one person, or use the Just me shortcut without creating a debt.
  • Refresh from GitHub on screen focus, app foreground, or pull-to-refresh while retaining the latest valid cached data during transient failures.
  • See spending by category and payment method, follow optional group and category budgets, and calculate remaining-per-day guidance for a trip.
  • Keep legacy expenses valid when category or payment-method metadata is absent, with explicit Uncategorized and Unspecified presentation.
  • Protect edits and deletes with GitHub blob identifiers so a concurrent remote change is never overwritten silently.

Release gate

The code and automated coverage represent Phase 1 plus the CR-001 spending increment. Before this becomes a stable release, the complete product loop must pass on physical Android devices with two real GitHub accounts.

No stable APK is published yet

This is a development milestone, not a download announcement. Follow the repository for a tagged release after physical-device acceptance.

Known constraints

  • Android is the only supported release target.
  • Reads and writes require a network connection.
  • Groups are owned by personal GitHub accounts.
  • One currency is used per group.
  • Settlements cannot yet be recorded as paid.
  • There are no receipt images or attachments.
  • There is no percentage or exact-amount split.
  • Push notifications are not included.

For contributors

The repository documents product rules, architecture, automated coverage, and the manual acceptance run. Start with the product requirements if you are changing behavior, then use the architecture and testing guides to preserve the data model and safety guarantees.
